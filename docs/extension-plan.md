# Safe-anchor extension: prospective evaluation contract

The inherited affine model, exclusion precedence, linear unauthorized penalty,
trusted history, epoch/counter ordering, and ordinary certificate remain fixed.
This plan is written after a pointwise algebra pilot and before the extension
implementation and its workload measurements. It is not a preregistration of
the inherited exploratory cases.

## Hypothesis and falsification

A fully verified safe old plan has multiplicity equal to its old policy
indicator. Substituting that invariant into the new defect should eliminate all
unchanged-fragment pair queries. Let r deleted and a added future occurrences
remain after exact multiplicity-preserving matching. The proposed update needs
only O(1+r+a+a^2+ar) masked counts per epoch, plus complete input validation and
matching. It permits a new trusted policy but not a changed affine context,
epoch list length, or declared history. A valid but unsafe old transcript is
not an anchor. A prefix-only old transcript is not an anchor.

Reject the hypothesis on any mismatch with full checking or either finite
oracle; do not adjust the reported result to agree. A runtime advantage is not
a prerequisite for retaining a case. Cold checks include full base validation;
warm checks explicitly reuse an in-process verified immutable base. No
untrusted serialized Boolean or self-hash is a trusted checkpoint.

## Selection and measurements

Use exact retained inputs plus newly generated benign inputs, independent
seeds from the inherited validation, and explicit removal/addition/policy,
empty-guard, history, epoch, prefix, and schema controls. Count attempted,
retained and actually compared cases separately. Keep total distinct new
configurations within 300 and original-plus-new records within 1000.

Measure full and warm update verification on exactly the same new input.
Include cold cost separately. Sweep N, number of base fragments K, mask
interval complexity E, and edit count; retain all repetitions, with one warmup
and five timed repeats. Report medians, IQR, sizes and reconstructed arithmetic
queries. Preserve inherited results without rewriting them. No operational
traffic or scanner deployment claim.

## General certified-counting comparison

Read exact primary descriptions of CPOG (JAIR 2025), projected CPOG (SAT 2025),
and VeriPB projected enumeration (CP 2026). A general exact Boolean count
encoding must preserve the application defect and deterministic auxiliary
assignments, not count SAT auxiliaries as fresh solutions. Measure no external
solver performance without actually acquiring and executing its toolchain.
A local reference Boolean backend is not a substitute for an upstream solver.
Generic proof-system expressiveness must not be confused with an automatic
encoding-specific complexity guarantee or a lower bound against that system.

## Resource and provenance rules

All scientific children: one affinity CPU, 2500-MiB address-space bound,
110/115 CPU seconds, 115-second alarm, 120-second outer process-group wall
bound. Standalone science remains standard-library-only. Optional external
baselines/builds are separately specified. Incoming original observations stay
unchanged; fresh results carry explicit new-run labels. General proofs are
written mathematical arguments, not a proof-assistant result.

## Timing-resolution pilot adjustment

The first unchanged 20-case timing pass returned zero CPU deltas on several
sub-millisecond operations. All of its observations are retained under
`results/update-bench-pilot/`; the uncollected-parent-status case is retained
separately. They are not the final performance table. Before the final pass,
replace one-call timings with per-operation doubling calibration to at least
50 ms of CPU per batch (maximum 4096 iterations), one batch warmup, and five
retained batches. Divide full batch times by their recorded iteration counts.
Keep both CPU and wall times. This changes timer resolution, not inputs,
inclusion rules, algorithm parameters, or an outcome threshold.
